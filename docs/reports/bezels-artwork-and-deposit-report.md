# Decisions taken alone

### 1. The three PNGs go into the repo's `assets/overlays/` — and can never overwrite anyone

The question the brief asked, and the answer was already in `install/arch.sh`.

`assets/overlays/` is excluded **from the OTA rsync and from `arch.sh`'s
tar**. The loop after it only copies the directory **when absent** at the
destination:

```sh
for _keep in emu config assets/overlays assets/logos; do
  if [ -d "$PROJECT_ROOT/$_keep" ] && [ ! -e "$GAMECORE_PATH/$_keep" ]; then
```

**Conflicts are resolved at whole-directory granularity, not per file** —
which makes the answer simple:

| situation | what happens to the player's bezel |
|---|---|
| fresh install | they have none; they receive the three |
| existing box, OTA | **nothing at all** — the directory exists, it is skipped |
| existing box, `arch.sh` re-run | **nothing at all** — same loop, same skip |

A player who already had a bezel cannot be overwritten by a release. The flip
side: an existing box does not receive them either — that is part B.

No new location under `catalog/` was invented: the six existing bezels
already live in `assets/overlays/`, and a second place would be a second
answer to "where does a bezel live".

**To undo:** delete the three files. Nothing else depends on them.

### 2. Generated by a committed script, not dropped in as binaries

`scripts/make-console-bezel.py`. A blob in git cannot be reviewed; the ratio
is the one thing a bezel cannot afford to have wrong by a pixel. Here the
ratio is an argument and the arithmetic is eight lines.

**Pure stdlib, not Pillow** — the same reason `_alpha_bbox` is hand-written
rather than shelling to ImageMagick: no install script puts an imaging library
on a box. (Pillow happens to exist in this venv; it was not used.)

**To undo:** replace the PNGs with your own; the script becomes unnecessary.

### 3. A gradient and a bevel — nothing borrowed

Two dark side panels, a coloured edge line at the hole. Green for the Game
Boy, purple for the Color, indigo for the Advance, so they are tellable at a
glance. No box art, no logo. Community bezel packs are other people's artwork
— GameCore does not host them, ship them in the ISO, or fetch them unasked;
the same posture as BIOS files and keys.

**To undo:** `--top`, `--bottom`, `--accent` are options.

### 4. A slots route on the core, rather than a decoder in the addon

`GET /api/overlays/{system}/slots` answers what `choices` cannot: **every
slot, filled or not**, with the measured hole and its reduced ratio. `choices`
is about one game and lists only what exists — a console with no bezel is
simply absent from it, and from a browser that is indistinguishable from an
upload that silently failed.

The addon could have read `assets/overlays/` itself. It would then have needed
a second alpha decoder to know the hole — two answers to a question that
already has one.

`DELETE /api/overlays/{system}/consoles/{console}` came with it: without a
delete, a bezel dropped on the wrong console could only ever be replaced, and
the cascade would keep resolving it ahead of the system bezel.

**To undo:** both routes are additive; nothing existing depends on them.

### 5. The addon degrades instead of breaking against an older core

**The decision that avoided breaking the box.** An addon updates on its own
`git pull`; the core updates by OTA: the two versions are independent. The
addon was published **before** the core release existed, so on the box it
would talk to a core that knows neither `/slots` nor `/consoles/…`.

Without a fallback, `/slots` answered 404 and the overlays screen became
unusable — including for the **system** bezel, which worked before. The update
would have been a net regression.

The fallback is the system slot alone, with a sentence in the UI saying why.
Presence is read off the disk — **reading** the player's data is allowed; it
is **writing** outside the addon's directory that `api: 1` forbids — but the
hole stays null rather than guessed: measuring it means decoding alpha, the
core owns that.

**To undo:** delete `legacy_slots()`. Only once the core release is
everywhere.

### 6. Merging the addons repo's `main` — therefore publishing

Explicitly authorised beforehand. `gamecore-addon update` is a
`git pull --ff-only` on the checkout that tracks `main`, **no tag, no CI**: it
is in production the moment the update command runs.

Riskless thanks to decision 5: on the box, the overlays screen behaves exactly
as before until the core catches up.

**To undo:** `git revert` merge `8c44d39`, then `gamecore-addon update`.

# Part A — the three PNGs

| file | console | measured hole | ratio |
|---|---|---|---|
| `mgba.gb.png` | Game Boy | `1200x1080+360+0` | **10:9** |
| `mgba.gbc.png` | Game Boy Color | `1200x1080+360+0` | **10:9** |
| `mgba.gba.png` | Game Boy Advance | `1620x1080+150+0` | **3:2** |

Holes measured by `bezels.hole_of()` — the real alpha decoder, not the
generator. 1920×1080 frame, the one `window_rect` forces. ~22 KB each.
(The frames were later redrawn with a recess/line/mat/glow structure, and
later still replaced on the box by The Bezel Project system-art frames — the
repo keeps the generated ones.)

## Proven by a test, not by inspection

`test_bezels_consoles.py` adds four tests on the shipped files:

- the ratio is **exact**, in integer arithmetic (`w * rh == h * rw`), not
  within a tolerance;
- the hole is centred within one pixel — otherwise `is_plausible` would
  refuse every screen measurement and the drift correction would never apply
  again;
- the filename names a console `roms.consoles` actually declares;
- if a pack ships one console bezel it ships **all of them** — two dressed
  consoles and a third falling back to a 1:1 frame reads as a cascade bug, not
  a missing file.

**And the test is not vacuous.** Verified by regenerating `mgba.gba.png` at
10:9:

```
E  AssertionError: mgba.gba.png: hole is 1200x1080 = 1.1111, gba renders at 3:2 = 1.5000
E  assert (1200 * 2) == (1080 * 3)
```

## "A GBA game is no longer bitten"

Measured end to end, core + addon running on a test root:

```
Pokemon Emerald (USA).gba   console=gba  source=console   hole=1620x1080+150  asset=mgba.gba.png
Zelda Oracle (USA).gbc      console=gbc  source=console   hole=1200x1080+360  asset=mgba.gbc.png
Tetris (World).gb           console=gb   source=console   hole=1200x1080+360  asset=mgba.gb.png
Compil (Europe).zip         console=None source=declared  hole=1080x1080+420  asset=-
```

1620/1080 = **1.5000**. The hole is 3:2, no longer 1.14.

The `.zip` falls back to the system level: an ambiguous extension names no
console — the previous phase's decision, visible here.

# Part B — deposits from ROM Manager

The overlays modal becomes **one card per slot**, empty ones included:
preview, state (`in place` / `no bezel`), the filename the slot expects, the
measured hole and ratio, a drop zone, a remove button.

## The addon contract is intact, and tested negatively

`assets/overlays/` belongs to the core. Everything relays over loopback: the
core decides filename, destination and validation.

The most important test in `test_overlays.py` is a **negation** — after an
upload, the addon must have created **no file anywhere**:

```
  ok   upload without a core answers 503, not 500
  ok   nothing was written under DATA
  ok   nothing was written under PATH
  ok   no assets/overlays was created at all
```

Writing the PNG from the addon would have been one line shorter, would have
worked on a box, and would have turned the rule into "an addon writes wherever
it can reach". Rule 6 was added to the addons repo's `docs/SECURITY.md` so it
is written down, not just observed.

## The opaque-image refusal arrives with its words

The relay returns the core's **status and body**. Measured:

```
HTTP 422
{"detail":"A bezel needs a transparent area for the game to show through,
 and this image has none the decoder can read. Save it as a PNG with an alpha
 channel — JPEG cannot carry one at all."}
```

And no file created. Swallowing it into a generic "failed" would discard the
only explanation the player ever gets.

## Two genuinely distinct roots

The owner was right to insist, and **it caught a real false pass.**

`GAMECORE_BACKEND_PORT` defaults to 8765 — which on this machine is the
**box's real backend**. The first draft of `test_overlays.py` talked to it for
real and measured its answers instead of the addon's: three checks "failed"
reporting 405/404 — the deployed core's replies. The file now pins a dead port
picked by the OS, and its first check asserts the port is not the real one.

(Nothing was written to the box during that false start: the deployed core
lacked the routes and answered 405. Verified on mtimes afterwards.)

`test_paths.py` additionally covers `OVERLAYS_DIR` under both roots, including
the fallback of a box that has not taken the P3 OTA.

from backend.services import bezels
for rom in ("Tetris (World).gb", "Zelda Oracle (USA).gbc", "Pokemon Emerald (USA).gba"):

**1200** for the other two.

route, not on the filesystem. An argument for going through ROM Manager.

# What I am not sure of

1. **The frames are plain and that is intended.** Whether a bezel is beautiful
   cannot be proven from here. Two panels and an edge line: judged from three
   metres, and part B exists so the owner can replace them without me.
2. **A console's expected ratio was not yet declared in the pack.** The UI
   shows the *measured* ratio ("3:2") but could not say "and this console
   expects 3:2" — so it would not warn about a 16:9 frame dropped on the Game
   Boy. A `ratio` field in `roms.consoles` would fix it. (It later did —
   v1.2.15.)
3. **The 28 px bevel is an eyeballed number**, on an image only seen as a
   preview. It may be too subtle on a TV.
4. **The UI was never rendered in a browser.** The JS is syntax-checked
   (`node --check`), the routes are tested end to end against a real core, but
   the card layout was never displayed.
5. **The legacy-core fallback triggers on a 404 from `/slots`.** If a core
   ever 404s for another reason, the screen will wrongly say "your box is
   old". Preferred over a version probe, which would require the core to
   announce one.
6. **`.iso` and `.rvz` stay unattached for dolphin** — the previous phase's
   decision: the console cards appear for GameCube and Wii, but most Dolphin
   games keep resolving at the system level.
